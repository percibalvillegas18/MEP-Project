MEP PROJECTS PORTAL — VERSION 007.4
===================================

REQUIREMENTS
------------
- XAMPP with PHP 8.1+ and MySQL 8.0+ or MariaDB 10.4+
- PHP PDO MySQL extension
- PHP fileinfo, GD, and cURL extensions for work-plan photo validation/storage
- Chrome or Microsoft Edge for Print / Save as PDF

LOCALHOST MODE
--------------
Requests using localhost, 127.0.0.1, or ::1 automatically use development mode when MEP_APP_ENV is not configured. This supports XAMPP and PHP's built-in server, enables exact local diagnostics, and allows the default local MySQL root account. Public hosts remain in production mode by default.

NEW / EMPTY INSTALLATION
------------------------
1. Copy the `MEP_Projects_Version_007.4` folder into C:\xampp\htdocs\MEP Projects.
2. Start Apache and MySQL.
3. Open phpMyAdmin.
4. Import database.sql.
5. Configure config.php or the environment values.
6. Open setup_admin.php and create the first administrator.
7. Sign in and test each module.

EXISTING DATABASE UPGRADE
-------------------------
1. Export the database and copy uploads outside htdocs.
2. Put the portal in maintenance mode and stop writes.
3. Import `database_upgrade.sql` once. It combines all Version 003–007 additive migrations and preserves existing records.
4. Confirm the final verification query returns 0 unmigrated memberships.
5. Keep project_members during the rollback window; Version 007.4 retains Version 003 dual-write compatibility.
6. Deploy the code, clear PHP opcode cache, and run the checks below.

REQUIRED PRODUCTION ENVIRONMENT
-------------------------------
- MEP_APP_ENV=production and MEP_APP_DEBUG=false
- MEP_DB_USER / MEP_DB_PASS: dedicated non-root account
- MEP_ALLOW_SELF_SIGNUP=false
- MEP_APP_BASE_URL: public HTTPS portal base URL
- MEP_SMTP_HOST, MEP_SMTP_PORT, MEP_SMTP_USER, MEP_SMTP_PASS, MEP_SMTP_FROM
- MEP_EVIDENCE_STORAGE_DRIVER=s3, plus endpoint, region, bucket, access key,
  secret key, object prefix, and path-style setting from `.env.example`
- Grant the storage identity only PutObject, GetObject, HeadObject, and
  DeleteObject permissions for the configured object prefix.
- Never set MEP_ALLOW_INSECURE_LOCAL_DB=true in production.

OBJECT-STORAGE MIGRATION
------------------------
1. Configure the MEP_EVIDENCE_S3_* values and deploy Version 007.4.
2. Existing local evidence remains readable while local mode is selected. Before
   switching production to s3, copy existing `uploads/workplan` files to the
   configured bucket prefix. Legacy database filenames are resolved under that
   prefix automatically and do not require a database rewrite.
3. Upload and open a test photo, restart the application container, and open it
   again. Then remove it and run `php tools/process_queues.php` to verify deletion.
4. Keep the bucket private unless MEP_EVIDENCE_PUBLIC_BASE_URL intentionally points
   to a protected CDN. Otherwise the portal issues short-lived signed GET URLs.

DEBUG / TEST ERROR DISPLAY
--------------------------
Set MEP_APP_ENV=development and MEP_APP_DEBUG=true in the Apache/PHP environment while debugging. HTTP 500 pages and JSON errors will show the exact exception, file, line, source syntax, controller/class, form action, MVC action file, possible cause and stack trace.

Before production deployment, set MEP_APP_ENV=production and MEP_APP_DEBUG=false. Debug output can expose internal file paths and database details and must not be enabled on a public production server.

WARNING: database.sql drops the existing application tables. Never import it into a database containing records you need.

DATA SAFETY
-----------
Before importing database.sql, export any database records and copy any uploaded files that you need to keep. Store backups outside the XAMPP htdocs project folder.

ACCEPTANCE CHECKS
-----------------
- In an XAMPP command prompt, set the same MEP_DB_* values used by Apache and run:
  `C:\xampp\php\php.exe tools\xampp_acceptance.php`
  `C:\xampp\php\php.exe tools\test_pipeline.php`
  `C:\xampp\php\php.exe tools\e2e_lifecycle_test.php`
  All commands must pass. The pipeline/lifecycle test records run inside transactions and are rolled back.
- Request `/tools/validate_release.py`, `/config.php`, `/database.sql`, and `/database_upgrade.sql`; Apache must return 403.
- Login, logout, role permissions and project access work.
- Assign, edit, and revoke each project role; verify Viewer cannot write and Coordinator cannot edit BOQ.
- Submit two concurrent updates with the same assignment version; the second must return HTTP 412.
- Confirm assignment changes increment the target user's auth_version and end existing sessions.
- Project Progress opens in Standard, Compact and Full views.
- Heading, Group and Measurable Item rows display correctly.
- Material Submittal can establish the earliest BOQ Actual Start.
- Add, edit and delete a Work Plan record.
- Upload one before photo and up to five after photos.
- Open View / Print Report and confirm all photos render.
- Use Print / Save as PDF in Chrome or Edge.
- Test Project Progress report and XLSX exports.
- Confirm Audit History opens without a server error.
- Confirm Management Alerts show severity order Critical, High and Medium.
- Confirm Open Procurement and Missing Activity Dates load without an SQL error.
- Confirm PO, required, expected-delivery and actual-delivery dates save and display.
- Tamper with posted BOQ/discipline fields; Work Plan must retain the selected measurable BOQ values.
- Tamper with a Procurement MAS ID from another project; the request must be rejected.
- Edit Work Plan/Procurement from BOQ A to BOQ B; verify both A and B progress are recalculated.
- Issue a password reset; verify no password appears in UI/logs, the link expires, works once, and invalidates old sessions.
- Confirm the sidebar and login screen display Version 007.4 without a stage prefix.
- Confirm protected POST requests reject missing or expired CSRF tokens.
- In a test environment, confirm an intentional failure displays the diagnostic request ID and exact source location; then restore the code.

BACKUP
------
Keep the database and object-storage backup until all acceptance checks pass.
